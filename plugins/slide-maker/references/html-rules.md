# HTML の書き方と描画の規準

SKILL.md の 4 章の細則。断片（`<元データ>/slides/NN-X.html`）を書く前に読む。確認用の画像（`previews`）は、この HTML を Chromium で撮ったもので、PPTX の実描画ではない。型の一覧は [components.md](components.md)。

## HTML の書き方

- 1 枚 = `<section class="slide" data-layout="…">`（1280×720px）。部品は `pp-text`・`pp-shape`・`pp-line`・`pp-image`・`pp-table`・`pp-chart`・`pp-picture` だけ。**これ以外のクラスの文字や図は PPTX に出ない**。
- 見本（`assets/components/`）の断片の `data-note="題：…"` は、要素の役割を書いた目印。測定・検査・PPTX・案の選択ページには影響しない。
- スライドの型は `<section class="slide" data-layout="…" data-type="型名">` の `data-type` で示す（断片には付いている。コピーすると残る。R1〜R3 の案は付けなくてよい）。型の名前の目印で、PPTX の中身には影響しない。
- 部位の名前は `data-part="…"` で付ける（部位を名前で呼ぶための目印。案の選択ページには出ず、測定・検査・PPTX にも影響しない。`data-role` とは別。`data-part="ヘッドメッセージ"` だけは、`base.css` が帯の縦中央に寄せるのに使う）。値は次のどれか: `タイトル`（`title`）・`ヘッドメッセージ`（`lead`）・`チャートタイトル`（`body`。数値・単位・凡例・時間軸を持つ型だけ）・`注釈`（`data-note="注：…"` の `caption`）・`出典`（`caption` に `data-chrome`）・`メッセージボックス`（面。`data-note="メッセージボックス：…"`）・`凡例`・`スティッカー`（タグ・チップなど小さなラベル）・`アクセント`（`f-emph`・`t-emph` の 1 点）・`チャート`（`pp-chart`。凡例・データラベル・軸ラベルはグラフの内部なので、チャートの中の部位としてコメントで名前を使って指す）。部品を足したら、該当する要素に付ける。コールアウト（吹き出し状の注記）とトラッカー（現在位置の表示）は、いまの型にはない（絵の中の吹き出しは絵の一部で、部位にならない）。同じ部位が 1 枚に複数あるときは、スライド内の出現順（左上から右下）の番号で呼び分ける（例: スティッカー②）。
- 位置は `style="left;top;width;height"`（px）。文字には必ず幅を付ける。面と文字は兄弟要素にし、文字の中心を含む面が背景色になる。
- 文字: `data-role` = `title|lead|body|caption|display`（`subhead` も使えるが、断片の小見出しはふつう `var(--fs-subhead)` をインラインで引く）。`title` は題（名詞句 20 字以内）、`lead` はヘッドメッセージの帯の中の文（判断を言い切る 30〜60 字。チャートタイトルは `body`（19px）で書く）。表紙・裏表紙の題と副題は `data-ph="title|subtitle"`（位置はテンプレート）。箇条書きは `<div class="pp-text"><ul><li>`。`pp-text` の中の段落は `p`・`div`・`li` を直下に並べる（1 段落だけなら裸の文字でもよい）。`display:inline` 系の `div` は段落にならず、前後の文字と同じ段落の行内の文字として取り込む（一部だけ書式を変えるなら `span` でもよい）。入れ子の `ul`（`li` の中の `ul`）と、`p` と混ざった裸の文字は PPTX に入らず、`textLost` で止まる。
- 色は下の「色の規約」の範囲で使う。`var(--accent)` などの変数を使うと、設計図の色に自動でそろう。
- 文字サイズは `:root` の変数で決まる（既定 px）: 題 `--fs-title`（37）・ヘッドメッセージ `--fs-lead`（27）・本文 `--fs-body`（19）・注記 `--fs-caption`（16）・出典・脚注 `--fs-source`（14）・表紙の題 `--fs-cover-title`（40）と副題 `--fs-cover-sub`（22）・小見出し `--fs-subhead`（22）、倍率 `--num-scale`（大きな数字）・`--chart-scale`（グラフ内の文字）。`data-role` は役割どおりの変数を引く。**断片に `font-size` を px で直書きしない**。役割は `data-role`（`title|lead|body|caption|display`）か `var(--fs-*)`、大きな数字は `calc(Npx*var(--num-scale))` で書く。直書きしてよいのは、変数にできない理由があるときだけ（理由をコメントに書く）。小見出し（箱・列の見出し）は `var(--fs-subhead)`、出典・脚注は `var(--fs-source)`。
- 本文 14pt（約 19px）以上、注記 10pt（14px）以上。出典を書くときだけ、`data-role="caption" data-chrome` で本文領域の下端（`top:calc(var(--area-y) + var(--area-h))`。標準は y 640〜664）に置く。領域が標準より狭いテンプレートでは、出典が上がって本文と重なるので、`overlap` の指摘に従って本文の位置を直す。
- 視線誘導: 読む順は **Z の法則**（左上 → 右上 → 左下へ斜め → 右下）に従い、始点（題・結論）を左上、終点（承認を求める対象・結論）を右下まで届かせる。文の寄せ方は変えない（文は左寄せ。右寄せは数字の列だけ）。使える場面では次の 3 つも使う。**矢印効果**（矢印で読む順・因果を示す。循環は輪と矢印で回して見せ、直線の矢印だけにしない。矢印は矢じり付きで、手順・因果の図には必ず入れる）、**孤立効果**（目立たせたい点だけ色・大きさを変える。強調色の範囲で）、**類同の法則**（同じ種類の要素は形・色・大きさをそろえ、違う種類は変える）。
- 画像はアイコン（`icons/<名前>-<accent|emphasis|white|gray>.svg`。名前は `icons.md` の一覧にあるものだけ。`alt` と `data-role="icon"` が必須。写真は `data-role="photo"`、ロゴは `data-role="logo"`）と利用者の写真だけ。
- 重ねる図（ベン図など）は、重なる要素の両方に `data-overlap`。
- 絵（`pp-picture`）: 型に当てはまらない図（NW 構成図・トラフィックフロー・障害動作・自己紹介・画面への注釈）は、`<div class="pp-picture" data-alt="…" style="left;top;width;height"><svg viewBox="0 0 幅 高さ">…</svg></div>` と書く。`build` が絵の範囲だけを透過・3 倍の PNG にして、1 枚の画像として貼る（**絵の中身は PowerPoint で直せない**。題・ヘッドメッセージ・チャートタイトル・注釈は編集できる文字）。`data-alt`（絵の内容 1〜2 文）は必須。絵の中の色は `sv-f-*`（塗り）・`sv-s-*`（線）のクラスか `var(--…)` だけ、文字は 14pt（約 19px）以上。絵の内部の色と重なりは検査されない。絵全体とほかの部品の重なり・本文領域外は検査される。書き方・部品・図の種類ごとの作法は [picture-craft.md](picture-craft.md)。
- グラフ: `data-chart='{"type":"bar|barh|line|pie|stacked|waterfall","categories":[…],"series":[{"name":"…","values":[…]}],"highlight":番号,"fmt":"#,##0","totals":[…],"axis":{"min":0,"max":600,"major":150}}'`。`axis`（任意）は値の軸の最小・最大・目盛の間隔を固定する。省くと自動。小グラフを並べるときは、全パネルに同じ `axis` を書く。ブラウザのプレビューは近似で、実際は PowerPoint のグラフになる。

## 色の規約

使う色は**無彩色（白・黒・グレー）＋基調 1 色＋強調 1〜2 色**の範囲に、**資料全体で**収める（色相の系統を数える）。基調色・強調色は設計図の `基調色:`・`強調色:`（強調色は 2 色までをカンマ区切り。なければテンプレートの色）。蛍光色・彩度の高すぎる色は使わない。文字と背景のコントラストは 4.5 以上。グラフの系列色もこの範囲の濃淡で表し、色だけで意味を分けない（凡例やラベルを併用する）。`build` が検査し、`colorRange`・`colorNeon`・`colorContrast` はエラー。`theme.css` は設計図の色から色の変数（`--accent` など）を作る。使っても、色を直接書いてもよい。

## 描画の規準

- 配置の 4 原則: ①縦軸・横軸を決めてから置く（縦＝対象・分類・プレイヤー、横＝時間・工程・判断軸）。②同じ語を 1 枚に 2 度書かない。2 度出たら軸・見出しにくくり出す（軸ラベル・固有名・単位は数えない）。③1 つの図に 3 つ目の軸を持ち込まない。要るなら左右か上下に分ける。④数値の大小は、面積・長さ・太さに比例させる。
- 斜めの線: `pp-line` に `data-dir="diag"`（箱の左上→右下）または `data-dir="diag-up"`（左下→右上）を付けると、箱の対角線を引く（太さは `border-top` か 3px。矢印は `data-arrow="end"`）。拡大の関係（注目枠から拡大の画面へ広がる 2 本）など、斜めが意味を持つ図だけに使う。HTML の確認画面では箱が塗られて見えるが、PPTX では線になる。他の要素と重なるので `data-overlap` を付ける。
- 記号文法（全ページで同じ意味にする）: 実線（`pp-line`）＝実績・確定／破線（`dashed`。`pp-line`・`pp-shape` に付ける）＝予測・計画・消える要素／点線（`dotted`）＝補助輪郭。塗り＝実績・自社／枠線のみ（`f-outline`）＝計画・目標／濃色（`f-accent`・`f-dark`）＝主役、淡色＝文脈。比較では要素の位置を変えない。破線・点線は PPTX の線種になる。縦の破線・点線は `vl` を足し（`pp-line dashed vl`）、`width:0` と `height` で指定する（`border-left` で描くため。足さないと縦線は破線に見えない）。
- 階調: 基調色に白を 28・52・75% 混ぜた 3 段（`--accent-soft`＝`f-soft2`、`--accent-mid`＝`f-mid`、`--accent-light`＝`f-light`）。基調色を `#RRGGBB` で指定しても同じ式で作る。パネル地は `--bg-soft`（`f-soft`）、罫線は `--line`（`hr`）。
- グラフの作法: 軸は 0 始まり（％・指数は例外）。目盛は 3〜6。単位は図の左上に 1 回。全要素に実数ラベル（`data-chart` は自動で付く）。目盛線は出さない（自動で消える）。凡例を離れた場所に置かない（系列は 3 本まで。複数系列の凡例はグラフの直下に付く）。複数のグラフを並べるときは `axis` で軸をそろえる。実績と予測の境界は図中に示す。チャートタイトル（`data-role="body"` の太字。`lead` はヘッドメッセージの帯に使う）は名詞句で、時点と単位を含める。1 枚に図を 2 つ以上置くときは、図ごとにチャートタイトルを図の真上に置く。
- 表: 列幅は最長のセルで決め、語の途中で折り返さない。空のセルは空欄か「なし」（ダッシュで埋めない）。
- 本体は、本文領域の下端近くまで使い切る。無所属の空白帯を残さない。
- 禁止: 多色グラデ・3D・角丸の多用（`.r` は 2px）・全幅のカラーバー・署名・ダッシュ（—。題・本文・表・注記のどこにも使わない）。アイコンは使えるが、飾りにせず、ラベルを添える。

## 自由設計（R）の指針

全ページを `slides/NN-R1.html`〜`NN-R3.html`（2〜3 案）で組む。`assets/components/` の型は見本で、なぞらず、そのページの主張に合わせて、構図・余白・強弱を考える。

- 先に決める: 読ませたい順（Z の法則）、主役の 1 点、余白の取り方。要素を詰めず、主役の周りは空ける。
- 案（R1〜R3）は構成を変える。**主役の種類**（グラフ・表・絵・画像・構図）まで変え、色や位置を少し変えただけの案にしない。主役が図・絵・表・グラフでない案は `review-page` の警告になる（表紙・裏表紙・区切りは除く）。
- 題とヘッドメッセージ（リード）の文字（既定: 題 37px・リード 27px・BIZ UDPゴシック・左寄せ）は固定で、`chromeSpec` で検査される。変えるときは `<元データ>/rules.json` に `{"title": {"size_px": 37, "align": "left"}, "lead": {…}}` と書く（`size_px` は theme.css の `--fs-title`・`--fs-lead` に反映される。`align` は検査だけで、断片で指定する。フォントは固定で、`font` を書くとエラー）。
- 区切りのページ（`data-layout="divider"`）は本文のレイアウトを使う。題は `data-role="title"` の大きさの規約を外すなら本文の題と同じ大きさにするか、題を置かない。
- 守ること（文字の大きさ・ヘッダー・フッターの帯・重なり・はみ出しは検査が止める）:
  - PPTX に出るのは `pp-*` の部品だけ。それ以外のクラスの文字や図は出ない。
  - 色は「色の規約」の範囲に収める。
  - 文字の大きさは `data-role` か `var(--fs-*)`。本文 14pt（約 19px）以上、注記 10pt（14px）以上。
  - 題・ヘッドメッセージ・出典の領域（ヘッダー・フッターの避ける帯）に、ほかの部品を置かない。
  - 重なり・はみ出しは `check` がエラーにする。重ねる図だけ `data-overlap`。
- 最初のページ（表紙・裏表紙も）の前に、`frontend-design:frontend-design` スキルを呼ぶ。そのスキルは Web の画面向けなので、PPTX に出せるものだけを使う。
  - **使う観点**: 構図（どこに何を置くか）、余白の取り方、強弱（主役の 1 点と、それ以外の落とし方）、視線の流れ、文字の大きさ・太さの階層、案どうしの構成の違い。
  - **使わない**: グラデーション・影・ぼかし・アニメーション・ホバーなどの動き、Web フォント、背景画像やノイズ、色の独自の選び方（色は「色の規約」の範囲）、`pp-*` 以外の部品。
- 一覧にないアイコンや絵記号は、その場でインライン SVG に描く（色は `sv-f-*`・`sv-s-*`）。
- 描いたら `check` で違反 0 件を確かめてから出す。
